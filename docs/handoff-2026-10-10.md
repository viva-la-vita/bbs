## 三、服务器环境 quirks（踩坑记录，务必遵守）

1. **服务器 `~/bbs` 不是 git 仓库**——compose/config 变更必须手动同步（Windows 粘贴到 SSH 的坑见下）。
2. **Windows→SSH 粘贴 CRLF 坑**：多行 heredoc 的 `EOF` 会带 `\r` 导致永不结束。用单行 `printf '%s\n' 'a' 'b' > file` 代替；长 sed 用单行并 `&& grep -n` 验证。
3. **nginx 日志是 json 文件**（`/dev/stdout` 软链陷阱：容器内 tail 会挂死）。宿主机分析：
   ```bash
   LOG=$(docker inspect -f '{{.LogPath}}' bbs-nginx-1)   # 已 80G+，别 docker logs
   tail -c 50000000 "$LOG" | sed -e 's/^.*"log":"//' -e 's/","stream.*$//' -e 's/\\"/"/g' -e 's/\\n$//' > /tmp/n.log
   ```
   日志格式：第 1 列 = X-Forwarded-For（真实 IP），最后一列引号 = UA，时间格式 `[10/Oct/2026:07:47:23 +0000]`（UTC）。
4. **bbs-nginx 前有 gateway-nginx**：真实客户端 IP 只在 `X-Forwarded-For` 里；`deny`/防火墙对真实 IP 无效，封 IP 用 `if ($http_x_forwarded_for ~* (前缀)) { return 403; }`。docker exec 进容器 sed 改 `/etc/nginx/conf.d/flarum.conf` + `nginx -s reload` 秒生效（容器重建会丢，需同步仓库）。
5. **宿主 ip6tables 的 INPUT/DOCKER-USER 都对 Docker 流量无效/不存在**，别走防火墙路线。
6. **docker exec 可能因高负载极慢**，优先用宿主机文件+`docker compose` 操作。
7. flarum CLI 交互命令（migrate/extension:enable 提示密码时）非交互会静默失败，用 `sh -c '... "$MYSQL_ROOT_PASSWORD" ...'`。
8. 部署流程以 `DEPLOY.md` + `docs/deploy-update-flarum-runbook.md` 为准；"Update Flarum" 锁站 = 跑 `php flarum migrate`（镜像构建会批量升级 `*` 扩展，属正常）。

## 四、下一个任务：抓出剩余的 CPU 大户

当前 load 24（正常应 ≤10）。方法（都已验证可用）：

```bash
# 1. 最近请求 top IP / 路径 / UA
LOG=$(docker inspect -f '{{.LogPath}}' bbs-nginx-1)
tail -c 50000000 "$LOG" | sed -e 's/^.*"log":"//' -e 's/","stream.*$//' -e 's/\\"/"/g' -e 's/\\n$//' > /tmp/n.log
awk '{print $1}' /tmp/n.log | sort | uniq -c | sort -rn | head      # top IP（正常用户几百，大户上万）
awk '{print $7}' /tmp/n.log | cut -d'?' -f1 | sort | uniq -c | sort -rn | head   # top 路径
awk -F'"' '{print $(NF-1)}' /tmp/n.log | sort | uniq -c | sort -rn | head       # top UA

# 2. 已知可疑对象（上次采样 10-10 07:00 UTC 窗口）
#    HeadlessChrome/152 7675 次（2.8%）：先查 grep "HeadlessChrome" /tmp/n.log | awk '{print $1}' | sort | uniq -c | sort -rn | head -5
#    判断标准：单 IP 占比 >2%、匀速刷同一路径、打 /api/* 而非页面 → 机器人

# 3. 确认后封禁（单行，本地已验证格式）：
docker exec bbs-nginx-1 sh -c 'sed -i "/server_tokens off;/a\\    if (\$http_x_forwarded_for ~* (IP或前缀)) { return 403; }" /etc/nginx/conf.d/flarum.conf && nginx -t && nginx -s reload'

# 4. 封后验证：新记录应全为 403；uptime 的 load 应回落
```

注意区分真人：单 IP 万次+/窗口、循环刷同页、假 UA（版本号不存在）、只打 API 不打静态资源 = 机器人；分散 IP + 正常 UA + 正常路径分布 = 真人。用户特别在意**勿误封真人**。
